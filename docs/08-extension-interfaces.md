# 08 · 可选扩展接口：真实模型 / 真实 GitHub（未接通）

## 8.1 为什么先定义接口而不接通

教学仓库的模型调用点是一个确定性 mock。要换成真实模型，必须满足两个
教学不变量：

1. 调用仍发生在 **T1 之后、T2 之前**的事务外窗口；
2. 调用必须是**幂等可重放**的（崩溃后重跑一次，结果应可接受或可重试）。

因此扩展点被设计成一个纯函数接口，而不是散落在引擎里的 http 调用。

## 8.2 模型扩展点（形状，未实现）

```ts
// 伪代码：接口形状，非本仓库导出符号
interface ModelPort {
  // 输入：已 snapshot 的会话上下文；输出：模型文本结果
  // 契约：实现必须幂等；调用必须在事务外
  complete(ctx: Snapshot): Promise<ModelResult>;
}
```

挂载约束（一旦真实接通必须遵守）：

- 不得在事务回调内发起 `complete()`；
- 超时与重试策略必须与"3 次 dropped 放行"对齐（毒模型响应也走死信）；
- 真实模型费用不可控 → 教学演示默认仍用 mock，真实接通需显式开关。

## 8.3 通道 / GitHub 扩展点（形状，未实现）

```ts
// 伪代码：接口形状，非本仓库导出符号
interface ChannelPort {
  // send 必须幂等：同一 messageId 被投递多次，外部副作用只能发生一次
  send(message: { messageId: string; convId: string; body: string }): Promise<void>;
}
```

- outbox 里的每条副作用都带稳定 `messageId`；
- 真实接通时，**外部系统必须自己实现幂等键校验**——`channel.db` 只能
  去重"本库见过的投递"，去不了外部已发生的副作用（见 `07`）。
- GitHub 写操作（建 issue、发评论）应视为高风险副作用，默认关闭，
  教学仓库不提供 token 配置入口。
